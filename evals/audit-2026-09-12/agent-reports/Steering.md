## Summary
Audited both skills, three write-docs references, `evals/REPORT.md`, counter-signal guidance, CLI help/JSON, normal tiers, and a real five-file lint run.
The largest defects are stale command/profile claims, no decidable procedure for register/unsupported-claim/hedging review, and compression guidance that provably creates semicolons and omitted `that`.
The steering violates its own gate: normal lint emitted 101 findings across five files (58 warnings, 43 suggestions), including 26 warnings in `write-docs` and 18 in `review-docs`.
The two skills disagree on genre routing and verdict/exit handling; the CLI has more fields and subcommands than either skill documents.
Word counts are 1,156/285/123/86/1,260 (write skill/references/review skill), 3,010 words total (excluding markdown punctuation is tool-dependent; `wc -w` reports 3,571).

## Findings
### F1: CLI invocation and documented JSON contract drift
- surface: `packages/slopvac/skills/write-docs/SKILL.md:48-60`, `packages/slopvac/skills/review-docs/SKILL.md:38-50,65,78-112`
- kind: defect
- evidence: Actual help says `Usage: slopvac lint [OPTIONS] TARGETS...`; shorthand `slopvac <file> --profile normal --format json --config /dev/null` does work (exit 0), but the skills omit the canonical `lint` subcommand and present no distinction between top-level shorthand and subcommand. Actual `lint --help` exposes `--category` (repeatable), `--disable` (repeatable), `--rules-dir` (repeatable), `--out`, `--open`, `--min-score`, `--max-per-100-words`, `--locale`, `--no-vale`, `--no-color`, `--verbose`, and `--explain-config`; none are described in the workflow. Actual JSON is `{schema_version, version, summary, documents}`; `summary` has `documents, words, findings, errors, warnings, suggestions, per_100_words, score, passed, categories`; each document has `path, profile, words, sentences, paragraphs, findings, categories, total_findings, errors, warnings, suggestions, per_100_words, score, passed, failure_reasons, unchecked`. The skill says “per-category table” but does not name `.categories`, and only names `documents[].unchecked` without saying it is an array.
- evidence: `slopvac --help` lists `cache`, `compile`, `explain`, `init`, `lint`, `reference`, `rules`; the skills mention only `lint`, `rules`, `explain`, `init`. `rules --help` also has `--category`, `--kind`, `--profile`, `--config`, `--rules-dir`; `explain --help` accepts `--format`, `--config`, `--rules-dir`; `init --help` accepts `--profile`, `--force`, `--path`.
- proposal: Replace write-docs lines 48-60 with: “Run `slopvac lint <file>... --profile <profile> --format json` (the top-level `slopvac <file>...` shorthand is equivalent). Read `.summary.score`, `.summary.per_100_words`, `.summary.categories`, and each `.documents[].findings`. Treat exit 1 as a gate failure from findings or thresholds. Treat exit 2 as an incomplete run: Vale was absent, failed, or skipped with `--no-vale`; keep native findings and report every `.documents[].unchecked` entry. Do not call the file clean.” Replace review-docs lines 41-50 with the same wording. Add after review-docs line 112: “Use `slopvac lint --out <file>` or `--open` only when a human-readable HTML report is needed; `--category`, `--disable`, `--rules-dir`, `--locale`, and threshold flags alter the run and must be reported.”
- expected effect: correctness, FP↓ (fewer agents following invalid/underspecified commands)
- confidence: high

### F2: Exit-code prose is partly right but incomplete and the skills disagree on verdict inputs
- surface: `write-docs/SKILL.md:48-63`; `review-docs/SKILL.md:45-50,98-213`
- kind: steering-drift
- evidence: `--no-vale` probe exits 2 and JSON still contains native findings, confirming the exit-2 claim. A normal run with findings exits 0 unless thresholds are exceeded (`write-docs` itself: 38 findings, score 86.2, exit 0); the skills say “Fix every ERROR” but never state that exit 0 does not imply zero findings. Review’s verdict includes `Register`, `Claims`, and `False positives`; write only says “Fix what it returns.” Review’s genre table excludes PR bodies, commit messages, and release notes even though write routes them to normal/change-comms. Review routes “decision records” to normal while write routes them to `internal` (same profile, different reference); write routes `reference` material to `internal-docs`, while review’s table calls it strict but never says to load `internal-docs`. Review says `slopvac rules --format json | jq '.categories'` “with recommended_for”; actual JSON has `.categories` and each category has `recommended_for`, so this is valid, but the surrounding instruction says “what is available” without telling the reviewer that `rules` lists all rules only when no profile is passed.
- proposal: Replace write-docs step 5 (lines 61-63) with: “Invoke `review-docs` with the same `genre` and `profile`. Copy its exact verdict shape and resolve its action before declaring the artifact done.” Replace review-docs lines 31-36 with: “Use the passed genre/profile. If none was passed: README/docs/guides/ADRs → normal; API/reference/runbooks/procedures/safety → strict; issue comments/notes/drafts → relaxed; PR bodies/commit messages/release notes → normal. Load the matching write-docs reference when one exists.” Replace review-docs lines 194-213 with: “`REVISE` if exit is nonzero, `documents[].unchecked` is nonempty, any ERROR exists, any claim fails, or any paragraph/sentence is removable. `PASS` requires exit 0, no unchecked rules, no ERROR/WARNING left unjustified, every claim checked, and no removable passage.”
- expected effect: correctness, FP↓
- confidence: high

### F3: Normal-tier claim about contractions and em dashes is false
- surface: `packages/slopvac/skills/write-docs/SKILL.md:36-39`
- kind: defect
- evidence: `slopvac rules --profile normal --format json` reports `ste-sentences.omitted-word-or-contraction`: severity warning, tier enforced; `prose-format.no-unicode-dash`: severity error, tier enforced; `ste-punctuation.semicolon-used`: warning/enforced. But `ste-practices.omitted-conjunction-that` is suggestion/advisory at normal. The skill sentence “normal ... reports every contraction and em dash” conflates a true contraction rule and dash rule with the separate advisory `that` rule, and “every contraction” is not a genre-specific recommendation. Baseline shows `omitted-word-or-contraction` human 5.75/1,000 vs AI 9.43/1,000 (AI:human 1.63), while no-unicode-dash human 0.28 vs AI 6.79 (20.55): they have very different FP profiles.
- proposal: Replace lines 36-39 with: “Match the profile to the surface. At `normal`, contractions and Unicode em dashes are enforced by `ste-sentences.omitted-word-or-contraction` and `prose-format.no-unicode-dash`; omitted `that` remains advisory. Use `relaxed` for informal prose when those mechanical constraints would reject correct voice. Confirm the exact tier with `slopvac rules --profile <profile> --format json`.”
- expected effect: FP↓ on informal/human prose; correctness
- confidence: high

### F4: Compression creates semicolons and omitted `that`; the skill does not counter it
- surface: `evals/REPORT.md:72-83`, `packages/slopvac/skills/write-docs/SKILL.md:70-71`
- kind: fp-risk
- evidence: Prior eval measured `ste-punctuation.semicolon-used` 1→15 and `ste-practices.omitted-conjunction-that` 5→15 from unguided to current/new steering, explicitly attributing both to compression and the 20-word cap. Current lines 70-71 say “One idea per sentence” and “About 20 words for an instruction,” but do not name semicolons or require `that`. Python probes: regex `[^.!?]+;[^.!?]+` on `Set the flag; restart the worker.` → `True`; a negative-lookahead probe for omitted `that` on `Make sure the flag is set.` → `False` (the current pattern misses this common construction), demonstrating that prose instruction must carry the rule rather than rely on the detector.
- proposal: Replace lines 70-71 with: “MUST Keep one idea per sentence. For procedures, keep each instruction at 20 words or fewer; split at the limit rather than compressing with a semicolon, omitted conjunction, or chained clauses. Write `that` after verbs such as `ensure`, `make sure`, `verify`, and `check` when it introduces the clause.”
- expected effect: FN↓ for semicolon/that compensations; FP↓ for compressed prose
- confidence: high

### F5: Sentence rules invite compensating tells
- surface: `write-docs/SKILL.md:70-86`
- kind: fp-risk
- evidence: “One idea per sentence” (line 70) can produce staccato fragments; `review-docs` itself fires `ai-tells-structure.emphasis-paragraph-metric` at line 183. “Delete any adjective...” (line 78) can produce bare noun stacks; the linter fires `ste-nouns.multiword-noun-too-long` five times in write-docs. “Every claim names a checkable particular” (line 77) can produce fabricated precision; counter-signals explicitly identify `non-round-number-ratio` as only a proposed inverse metric, and baseline has `ai-tells-content-shape.fake-specificity` at 0.09 human and 0.10 AI/1,000 (weak discrimination). “Attribute or own every claim” (line 83) can produce citation theater; the current regex probe `(?:research|experts|studies)\s+(?:show|agree|find)` on `Experts agree that the cache is safer.` → `False`, so this failure is not caught. “Take the position...” (line 80) can overstate uncertain evidence; “hedge only...” (lines 80-82) gives no test for balance.
- proposal: Replace lines 70-86 with: “MUST Keep one idea per sentence, but join fragments when they only create emphasis; preserve a short sentence when it carries a complete fact. Delete unsupported adjectives, not necessary qualifiers or domain modifiers; reread noun stacks after each cut. Name a checkable particular only when the source supplies it; never invent a number, citation, benchmark, or version. Attribute claims to a named source only when you can identify and verify that source; otherwise state the bounded observation or delete the claim. State the evidence-supported position. Add one hedge only when you can name its uncertainty; count hedges across the document and ensure they do not erase the main claim. Keep `that` and other function words when they clarify clause boundaries.”
- expected effect: both (FP↓ for staccato/noun-stack/fake specificity; FN↓ for citation theater and unsupported certainty)
- confidence: high

### F6: Review coverage is asserted, not procedural, for register and claims
- surface: `review-docs/SKILL.md:100-102,133-147`; `packages/slopvac-lint/docs/counter-signals.md:25-32`
- kind: coverage-gap
- evidence: Review says the skill sees “register, symmetry, or an unsupported claim” but supplies no auditable test for register or unsupported claims. It says “judge register” only in the verdict template (line 188). Counter-signals marks the expert-byline register test irreducibly judgement and says it is not emitted. Structural symmetry is covered only by “read headings alone” and “cut the longest paragraph by a third”; neither compares sibling sections. Hedging balance is mentioned in write-docs, not review-docs, with no count or denominator. Strawman contrast is present in linter judgement output (`ai-tells-structure.contrastive-inversion-remainder`) but the review skill never tells the reader to answer its question with evidence beyond generic line 91.
- proposal: Replace review-docs lines 133-147 with: “Read the document in four passes. (1) Register: write one sentence naming audience, purpose, and channel; highlight any sentence whose vocabulary, certainty, or address would be implausible for that audience; keep one quoted example. (2) Structure: list H2 headings and count paragraphs under each; flag repeated heading templates or sibling sections within 20% of each other when their topics differ. (3) Claims: make a table of every externally checkable claim with source/path/command and result; mark unsupported claims for deletion, not hedging. (4) Stance: count hedge tokens per paragraph and identify the document’s main claim; if most support sentences are hedged, revise or delete the claim. For each contrast, name the real alternative it answers; if none exists, delete the contrast. Record one quote and one action for every failed pass.”
- expected effect: FN↓
- confidence: high

### F7: Skills fail their own normal gate and impose a large always-loaded token cost
- surface: all five target files; lint run and `wc -w -l`
- kind: test-gap
- evidence: Real command `slopvac lint` over all five files at normal with `/dev/null` config returned 101 findings (0 errors, 58 warnings, 43 suggestions), summary score 86.4, 3.471 findings/100 words; `write-docs/SKILL.md` had 38 findings/1,156 words (26 warnings), `consumer-docs.md` 13/285, `change-comms.md` 5/123, `internal-docs.md` 12/86, `review-docs/SKILL.md` 33/1,260 (18 warnings). Representative self-fires: write-docs line 17 semicolon; line 97 30-word procedural sentence; line 98 61-word descriptive sentence; review-docs line 39 semicolon; lines 86, 93, 105, 179 omitted `that`; lines 162, 175, 200 passive voice. Word/line counts from `wc -w -l`: write skill 1,412 words/115 lines; consumer 336/44; change-comms 145/21; internal 104/11; review skill 1,574/215; total 3,571 words/406 lines (linter’s normalized document counts are 1,156, 285, 123, 86, 1,260).
- proposal: Keep the skills mechanically clean enough to avoid teaching contradictory examples: split long decision sentences, remove semicolons, replace passive instructional prose, and use `judgment` consistently or set locale explicitly. Move low-frequency rationale and CLI option catalog into on-demand references; retain only routing and workflow in always-loaded SKILL.md. Exact deletion candidate: review-docs lines 103-131 duplicates the write-docs project gate/config table and can become one sentence linking to write-docs (“Use write-docs’ gate-selection instructions; this skill only triages and judges.”). Exact deletion candidate: write-docs lines 104-115 repeats the same config/suppression policy already present in review-docs lines 150-179; replace with “For gate configuration and suppressions, follow review-docs §Change a rule.”
- expected effect: correctness, perf (lower prompt load), FP↓ (self-lint no longer teaches invalid style)
- confidence: high

### F8: Counter-signal coverage has no operational home for several named tells
- surface: `packages/slopvac-lint/docs/counter-signals.md:17-32`, `review-docs/SKILL.md:76-91,133-147`
- kind: coverage-gap
- evidence: Counter-signals names `non-round-number-ratio`, `named-specific-density`, `second-person-concrete-ratio`, `unhedged-stance-ratio`, `refusal-count`, `section-length-dispersion`, and `sentence-length-dispersion`; review-docs loads judgement rules but never asks the reviewer to compute or even inspect these document-level counters. It does not mention unsupported claims as a table, structural symmetry as a sibling comparison, register as a test, or strawman contrast as a real-alternative check. The only concrete procedure is heading extraction (line 142) and paragraph cutting (143).
- proposal: Add after review-docs line 91: “For document-level counter-signals, inspect (do not mechanically enforce) number specificity, named-specific density, reader-as-actor sentences, hedge-free sentence share, explicit refusals, section-length dispersion, and sentence-length dispersion. Compare the result with the genre and audience; record only an observed passage and a rewrite. A low or high metric is not evidence of authorship.”
- expected effect: FN↓
- confidence: medium

## Decommission candidates
- Remove the repeated CLI fallback prose from one skill; retain it in write-docs and make review-docs say “use the runner selected by write-docs.” This removes duplicated 4-line operational text while preserving behavior.
- Remove or demote the unconditional “normal reports every contraction and em dash” sentence; the actual tiers are rule-specific and the baseline shows very different human/AI ratios.
- Remove `review-docs` lines 103-131 as a second config/rules-selection policy, or replace it with a link to the single authoritative section.
- Do not ship `counter-signals.md`’s proposed thresholds as enforcement: the file itself says every threshold is inferred and requires calibration against the 147,473-word human corpus.

## Checked and fine
- CLI exposes all four documented subcommands and accepts qualified `category.rule` IDs for `explain`; `slopvac explain --help` confirms `--format`, `--config`, and `--rules-dir`.
- `rules --judgement --format json` emits qualified `rule_id`, `judgement_question`, `fix`, `exceptions`, `examples`, `scope`, and tier data; the review skill’s “use qualified rule_id” instruction is correct.
- Exit 2 behavior is real: `--no-vale` exits 2 while retaining native findings and emits `documents[].unchecked` (empty in the local no-Vale probe because no Vale rules were configured).
- `slopvac init --profile <profile>` is valid; `--force` and `--path` are available but undocumented.
- The references correctly separate released-artifact, change-communication, and internal-doc constraints; the main defect is duplication/routing drift, not the genre concepts themselves.
